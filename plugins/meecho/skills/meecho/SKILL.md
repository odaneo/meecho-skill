# Meecho

将本技能作为所有 Meecho 操作的唯一显式入口。把选择器后面的文字视为
自然语言请求，而不是终端命令。既接受下列英文操作名，也接受意思明确的
中文表达。

## 统一使用中文

- 本技能及后续新增的参考文件、界面文案和操作说明必须使用中文。
- 只有文件名、YAML 字段、`$meecho:meecho` 选择器和九个操作标识符可以
  保留英文。

## 读取档案规范

执行任何需要读取或修改声音档案的操作前，先读取
[`references/profile-schema.md`](references/profile-schema.md)。严格使用其中的
根目录、schema、档案文件、备份和删除规则；不得自行补充另一套档案结构。

执行 `build` 或 `update` 时，还必须读取
[`references/build-profile.md`](references/build-profile.md)，按完整作品划分
证据、排除封存作品，并让用户在写入前审阅事实。接受用户直接粘贴的文字、
宿主可完整读取的 `.md` 和 `.txt`，以及宿主可可靠提取正文的文档；当前 Codex
中继续支持有效、未加密的 `.docx`。不安装或调用文档转换器。

执行 `write` 或 `revise` 时，还必须读取
[`references/write-and-revise.md`](references/write-and-revise.md)，按内容优先的
顺序应用必要规则，执行连续汉字复刻保护，并且只在聊天中返回一份正文。

执行任何操作时都必须读取
[`references/privacy-and-permissions.md`](references/privacy-and-permissions.md)。
其中的操作矩阵决定哪些动作只读、哪些明确请求可以直接执行、哪些动作需要
审阅确认，以及 `delete` 的二次确认要求。

## 严守边界

- 仅在宿主明确激活本技能后继续。
- 不要把“使用 Meecho”、普通润色请求或普通写作请求视为激活。
- 不要在本插件之外复制或安装第二份 `meecho` 技能。
- 原始作品文件和生成的声音档案必须保存在本插件和当前项目之外；粘贴的原文
  不得另存为中间文件。
- 不得训练、微调、继续预训练或以其他方式修改模型。
- 不得自行编造 Meecho 参考文件中没有定义的档案路径、数据结构或流程。
  如果缺少所选操作必需的参考文件，立即停止并说明当前版本尚不支持该操作。

## 选择一个操作

仅当已经明确调用本技能，并且请求意图没有歧义时，才根据自然语言判断操作。
如果无法确定，只简短列出相关选项。

- `build`：根据用户选定或直接粘贴的完整作品首次建立声音档案。
- `write`：根据主题或要求，使用默认或本次点名的声音档案创作新文本。
- `revise`：使用默认或本次点名的声音档案，在保留事实和原意的前提下修改文本。
- `update`：根据新选定或直接粘贴的完整作品更新现有声音档案。
- `remember`：持久保存用户明确提出的偏好或纠正。
- `status`：列出声音档案总数和全部合法 `profile_id`，标出默认档案；按需报告详细状态。
- `switch`：把用户精确点名且确实存在的声音档案设为新的默认档案。
- `export`：将档案复制到用户指定的位置，不改变原档案。
- `delete`：只有经过第二次确认后，才能删除选定档案。

每次只执行用户选择的一个操作。不得在写作或润色时暗中修改声音档案。

## 遵守权限规则

- 将 `status`、`write` 和 `revise` 视为只读操作。
- 执行 `write` 和 `revise` 时，只读取必要的档案内容，并直接在聊天中返回
  完成后的文本。不要创建草稿文件。
- 执行 `build` 和 `update` 时，先显示事实或变更审阅摘要及准确路径；只有用户
  确认审阅结果后才能写入。
- 执行 `remember` 时，只有用户明确表达长期保存意图才写入。复述保存内容和
  路径后直接执行，不再追加 Meecho 对话确认；临时要求或意图含糊时不得保存。
- 执行 `switch` 时，目标 `profile_id` 精确存在即可直接安全更新并报告结果，
  不再追加 Meecho 对话确认；不得修改任何声音档案内容。
- 执行 `export` 时，用户已经明确给出安全、准确且不会覆盖现有内容的目标即可
  直接创建副本并报告结果。目标不明确、不安全或将发生覆盖时先停止并询问，
  不得修改原档案或默认覆盖。
- 执行 `delete` 时，显示准确的目标路径，再次请求用户确认。没有得到明确
  确认时，不得进行任何修改。
- 上述“无需追加确认”不表示可以绕过 Codex 客户端自身的文件系统授权机制。

## 保持回复简洁

直接说明阻塞原因和所需权限。操作成功后，只返回用户需要的结果；不要添加
风格评分，也不要声称输出“像用户本人”。
