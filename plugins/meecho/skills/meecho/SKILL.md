# Meecho

将本技能作为所有 Meecho 操作的唯一显式入口。把选择器后面的文字视为
自然语言请求，而不是终端命令。既接受下列英文操作名，也接受意思明确的
中文表达。

## 统一使用中文

- 本技能及后续新增的参考文件、界面文案和操作说明必须使用中文。
- 只有文件名、YAML 字段、`$meecho:meecho` 选择器和八个操作标识符可以
  保留英文。

## 读取档案规范

执行任何需要读取或修改声音档案的操作前，先读取
[`references/profile-schema.md`](references/profile-schema.md)。严格使用其中的
根目录、schema、档案文件、备份和删除规则；不得自行补充另一套档案结构。

## 严守边界

- 仅在宿主明确激活本技能后继续。
- 不要把“使用 Meecho”、普通润色请求或普通写作请求视为激活。
- 不要在本插件之外复制或安装第二份 `meecho` 技能。
- 原始文档和生成的声音档案必须保存在本插件和当前项目之外。
- 不得训练、微调、继续预训练或以其他方式修改模型。
- 不得自行编造 Meecho 参考文件中没有定义的档案路径、数据结构或流程。
  如果缺少所选操作必需的参考文件，立即停止并说明当前版本尚不支持该操作。

## 选择一个操作

仅当已经明确调用本技能，并且请求意图没有歧义时，才根据自然语言判断操作。
如果无法确定，只简短列出相关选项。

- `build`：根据用户选定的原始文档首次建立声音档案。
- `write`：根据主题或要求，使用当前声音档案创作新文本。
- `revise`：在保留事实和原意的前提下修改用户提供的文本。
- `update`：根据新选定的原始文档更新现有声音档案。
- `remember`：持久保存用户明确提出的偏好或纠正。
- `status`：报告当前档案、版本、来源数量和最近更新时间。
- `export`：将档案复制到用户指定的位置，不改变原档案。
- `delete`：只有经过第二次确认后，才能删除选定档案。

每次只执行用户选择的一个操作。不得在写作或润色时暗中修改声音档案。

## 遵守权限规则

- 将 `status` 视为只读操作。
- 执行 `write` 和 `revise` 时，只读取必要的档案内容，并直接在聊天中返回
  完成后的文本。不要创建草稿文件。
- 执行 `build`、`update` 和 `remember` 时，先显示准备写入的本地档案位置，
  再请求文件系统写入许可。
- 执行 `export` 时，先显示来源和目标位置，再请求创建副本的许可。
  不得修改原档案。
- 执行 `delete` 时，显示准确的目标路径，再次请求用户确认。没有得到明确
  确认时，不得进行任何修改。

## 保持回复简洁

直接说明阻塞原因和所需权限。操作成功后，只返回用户需要的结果；不要添加
风格评分，也不要声称输出“像用户本人”。
