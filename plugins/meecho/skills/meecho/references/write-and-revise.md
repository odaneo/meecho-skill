# 写作与润色协议

本协议只用于 `write` 和 `revise`。它规定如何把活动声音档案应用到一次具体
请求，同时保证事实优先、私人语料不被大段复刻，并且所有结果只在聊天中返回。

## 开始前检查

1. 确认宿主已经显式激活 Meecho，并且本次只执行 `write` 或 `revise`。
2. 按 `profile-schema.md` 解析 `config.json` 和活动档案路径。
3. 校验 schema、档案标识、目录边界和六个必需档案文件。
4. 如果没有活动档案、schema 未知、路径非法或文件不完整，立即停止。
5. 不得为了继续写作而创建空档案、修复档案或改写配置。

`write` 和 `revise` 都是只读操作。它们不得修改项目、声音档案、备份、原始
文章或其他本地文件，也不得把本次请求中的偏好自动交给 `remember`。

## 选择必要的档案内容

先理解当前请求，再只读取与它有关的档案部分：

- 从 `style-profile.md` 选择适用于当前文体和篇幅的已确认规律。
- 从 `attention-lens.md` 选择与当前叙述对象有关的观察方式。
- 从 `voices.md` 选择目标声音；对照观察只用于辨别差异，不能当成负面规则。
- 从 `preferences.md` 选择用户明确确认且与本次请求有关的偏好或反感。
- 从 `exemplars.jsonl` 选择少量短例句，只用于理解规律，不得拼接成正文。

不要一次性把全部档案内容塞进生成过程。不确定结论只能提醒模型保持谨慎，
不能当成稳定规律。反例和适用边界必须与对应规律一起考虑。

## 执行 `write`

1. 从用户请求中提取主题、事实、目的、受众、体裁、长度和必须保留的词语。
2. 先形成满足这些内容条件的正文结构。
3. 再应用本次选中的声音规律、注意力方式和明确偏好。
4. 删除只是在表面模仿例句、但不服务内容的措辞。
5. 执行复刻保护检查；命中时丢弃命中片段并重新生成。
6. 完成事实与格式检查后，只返回一份正文。

没有获得的事实不得自行补全。缺少的信息不影响安全写作时，可以使用中性、
可替换的表达；缺失信息会实质改变内容时，停止并简短询问。

## 执行 `revise`

1. 把用户提供的待修改文本视为事实和原意的主要来源。
2. 列出必须保留的事实、立场、专有名词、数字、引文和格式要求。
3. 只调整表达、节奏、观察角度和用户明确允许改变的结构。
4. 不得把档案里的题材、人物、经历或事实移植到待修改文本。
5. 如果风格规则会改变事实或立场，放弃该规则。
6. 执行复刻保护和最终核对后，只返回一份修改后的正文。

除非用户明确要求，不要同时返回原文、逐条改动说明、多个版本或修改痕迹。

## 处理规则冲突

按下列顺序处理冲突，靠前者优先：

1. 用户在当前请求中明确提出的事实、目的和硬性格式。
2. `revise` 原文中必须保留的事实与原意。
3. 用户在当前请求中明确提出的表达要求。
4. `preferences.md` 中已经确认的偏好与反感。
5. 适用于当前任务的高可信声音规律及其边界。
6. 少量短例句提供的局部提示。

不得为了更“像”档案而牺牲准确性、可读性或用户当前要求。不得输出相似度、
风格分数，也不得声称结果就是用户本人会写出的文字。

## 复刻保护

在返回前，把候选正文与本次能够合法读取的私人文字逐一比较。检查范围包括：

- `exemplars.jsonl` 中本次读取的短例句；
- 用户直接粘贴在当前请求中的私人原文；
- 用户为本次操作明确重新选择、允许只读访问的有效且未加密的 `.docx`
  原始作品。

用户直接粘贴在当前聊天中的私人原文不受文件格式限制；文件形式的历史原文
只接受 `.docx`。

比较时只去除空格、制表符和换行等空白字符，不删除标点，不改写汉字。只要
候选正文中出现与上述私人文字完全相同、去除空白后不少于 20 个连续汉字的
片段，就停止使用该候选片段并重新生成。重新生成后必须再次检查，直到不再
命中或停止操作。

全局档案不保存原始 DOCX 路径和全文，因此没有重新选择有效的 DOCX 原始
作品时，只能检查当前上下文和档案短例句。此时不得声称已经对全部历史原文
完成逐字检查，也不得自行扫描磁盘寻找旧语料。

短引文如果是用户当前明确要求保留的原文，应保持准确并说明它属于用户提供的
引文；不得把保护规则当成悄悄改写引文的理由。

## 返回结果

- 正常完成时，只在聊天中返回一份最终正文。
- 不创建 `drafts`、`sessions`、临时稿、改写稿或其他项目文件。
- 不附带风格评分、相似度、模型分析过程或“像本人”的结论。
- 除非用户明确要求，不添加标题、前言、解释、备选稿或后记。
- 如果停止，只在聊天中说明具体阻塞原因，不留下部分文件。

## 停止条件

遇到下列情况立即停止：

- 活动档案不存在、无效或使用未知 schema。
- 当前请求无法确定是 `write` 还是 `revise`。
- 缺失信息会实质改变事实、立场或任务目标。
- 用户要求读取未选定的私人文件或封存语料。
- 复刻保护反复命中，无法在不损害内容的前提下安全改写。
- 用户要求在普通写作过程中保存草稿或暗中更新档案；应说明这是另一个明确
  的文件操作，不在本次 `write` 或 `revise` 范围内。
