# 隐私与权限协议

本协议适用于 Meecho 的八个公开操作。它定义每个操作可以读取什么、何时可以
写入、拒绝权限后如何收尾，以及结果应该出现在哪里。

## 共同边界

- 所有档案路径必须由 `profile-schema.md` 推导并通过规范化检查。
- 原始文章始终只读，只处理用户明确选择的文件，不自行扩大扫描范围。
- 私人档案、备份和原始文章不得进入插件目录、插件缓存、当前项目或 Git。
- 普通结果只在聊天中返回，不创建草稿、会话记录或隐藏的中间文件。
- 每次只执行一个明确操作，不把写作请求自动升级为管理动作。
- 只有宿主已经显式激活 Meecho 时，才应用本协议。
- 不得训练、微调、继续预训练或以其他方式修改模型。

文件系统审批只授权已经展示的准确动作和路径，不是对整个根目录的永久授权。
如果目标、范围或操作发生变化，必须重新说明并重新取得相应许可。

## 只读操作

`write`、`revise` 和 `status` 是只读操作。

- `write` 和 `revise` 按 `write-and-revise.md` 读取必要档案，并只返回聊天正文。
- `status` 只读取 `config.json`、活动档案的 `manifest.json` 和必要的存在性
  信息。
- 档案不存在时，`status` 直接说明“尚未建立活动档案”，不得创建
  `%USERPROFILE%\.meecho\`、空配置或占位文件。
- 只读操作不得修改访问时间以外的可见文件内容，不得建立项目内缓存。
- 只读操作不得暗中调用 `remember`，也不得建议用户为了完成当前正文而先
  保存偏好。

## `build`

1. 只使用用户明确选择的目标语料和可选对照语料。
2. 在聊天中展示新 `profile_id`、规范化后的目标档案路径和事实审阅摘要。
3. 确认目标档案尚不存在。
4. 请求对所展示目标的文件系统写入审批。
5. 只有审批通过后，才在安全临时位置形成完整档案并校验。
6. 校验通过后一次性放入目标位置，再安全更新 `config.json`。

用户拒绝审批或任一步失败时，不创建目标目录、空配置、临时档案或部分文件。

## `update`

1. 校验活动档案、schema、必需文件和全部规范化路径。
2. 在聊天中展示将更新的档案路径、新增来源范围和预期变更。
3. 请求备份和更新该档案的文件系统写入审批。
4. 审批通过后，先按 `profile-schema.md` 完成完整备份。
5. 在安全临时位置生成并校验完整的新版本。
6. 只有备份和新版本都有效时，才一次性替换原档案。

更新失败时保留原档案和已经成功完成的完整备份，不留下半成品。不得把
`update` 当成修复未知 schema 的手段。

## `remember`

`remember` 只保存用户在当前请求中明确要求长期记住的偏好或纠正。

1. 在聊天中复述准备保存的准确内容。
2. 展示将修改的活动档案及 `preferences.md` 路径。
3. 区分“用户明确偏好”和“用户明确反感”，不得把模型推测写入。
4. 请求备份和写入审批。
5. 审批通过后先备份，再安全改写和校验整个档案。

普通写作中的临时要求、模型从文章推测的规律、用户没有要求持久保存的反馈，
都不得自动进入 `preferences.md`。

## `export`

1. 展示规范化后的源档案路径和用户明确指定的目标路径。
2. 提醒用户导出副本仍包含私人声音信息，不应意外提交到 Git。
3. 确认目标不在插件目录、插件缓存或当前项目内。
4. 请求只对该目标创建副本的文件系统写入审批。
5. 审批通过后复制完整档案并校验副本。
6. 比较源档案前后文件清单与内容摘要，确保源档案没有改变。

`export` 不改变活动档案、不更新 `updated_at`，也不自动切换活动
`profile_id`。如果目标已存在，必须停止并让用户明确选择新位置或另行确认
覆盖；不得默认覆盖。

## `delete`

1. 解析并展示唯一、规范化的档案绝对路径。
2. 说明是否删除该档案的备份；默认保留备份。
3. 说明活动档案和 `config.json` 将如何变化。
4. 要求用户对所展示的准确路径进行第二次明确确认。
5. 只有第二次确认后，才能申请并执行该范围内的文件系统变更。
6. 只删除已经展示并确认的档案，不使用通配符，不扩大到其他档案。

第一次提出“删除”只是选择操作，不等于第二次确认。模糊答复、仅批准工具
权限或确认其他路径，都不能替代第二次明确确认。

## 权限被拒绝或操作失败

- 用户拒绝审批后立即停止，不反复请求，不改用其他目录绕过审批。
- 没有审批时不得先创建目录、锁文件、空文件、临时文件或备份。
- 已经写入安全临时位置但最终校验失败时，清理本次临时内容，并保留原档案。
- 不得留下可以被误认为成功档案的部分结果。
- 只在聊天中报告未执行的动作、准确目标和失败原因。
- 不把拒绝解释成允许只写一部分，也不自动降级为另一个管理操作。

## 路径与隐私检查

每次准备变更前都执行以下检查：

1. 将所有路径转换为规范化绝对路径。
2. 档案和备份必须位于固定的 `%USERPROFILE%\.meecho\` 内。
3. 档案目录不得是符号链接、目录联接或其他重解析点。
4. 导出目标必须是用户明确指定的位置，且不得位于插件或当前项目内。
5. 展示给用户的路径必须与实际操作路径完全一致。
6. 不记录原始文章路径到最终档案、插件、项目或测试日志。
