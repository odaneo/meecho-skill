# 隐私与权限协议

本协议适用于 Meecho 的九个公开操作。它定义每个操作可以读取什么、何时可以
写入、拒绝权限后如何收尾，以及结果应该出现在哪里。

## 共同边界

- 所有档案路径必须由 `profile-schema.md` 推导并通过规范化检查。
- 原始作品文件始终只读，只处理用户明确选择的文件或直接粘贴的文字，不自行
  扩大扫描范围；粘贴的原文不得另存为中间文件。
- 本地保存不等于离线推理。用户明确提供的作品正文会进入当前模型上下文；
  不得声称正文从未经过模型服务。
- 私人档案、备份、原始作品文件和粘贴的原文不得进入 Skill 安装目录、客户端缓存、
  当前项目或 Git。
- 普通结果只在聊天中返回，不创建草稿、会话记录或隐藏的中间文件。
- 每次只执行一个明确操作，不把写作请求自动升级为管理动作。
- 只有宿主已经显式激活 Meecho 时，才应用本协议。
- 不得训练、微调、继续预训练或以其他方式修改模型。

本协议区分 Meecho 的对话确认与当前客户端自身的文件系统授权。协议写明
“无需追加确认”时，用户当前清楚、具体的请求本身就是产品层授权；仍必须遵守
宿主实际显示的工具授权。目标、范围或操作发生变化时，必须停止并重新询问，
不能把原请求扩大成对整个根目录的永久授权。

## 只读操作

`write`、`revise` 和 `status` 是只读操作。

- `write` 和 `revise` 按 `write-and-revise.md` 读取必要档案，并只返回聊天正文。
- `status` 只读取 `config.json`、`profiles/` 的直接子目录、各候选档案的
  `manifest.json` 和必要的完整性信息。它返回合法 voice 总数、全部合法
  `profile_id`，并标出默认 voice；用户点名时可再返回该档案的版本、来源数量
  和最近更新时间。
- 没有档案时，`status` 直接说明“当前共有 0 个声音档案，尚未设置默认 voice”，不得创建
  `<USER_HOME>/.meecho/`、空配置或占位文件。
- 只读操作不得修改访问时间以外的可见文件内容，不得建立项目内缓存。
- 只读操作不得暗中调用 `remember`，也不得建议用户为了完成当前正文而先
  保存偏好。

## `build`

1. 只使用用户明确选择或直接粘贴的完整作品来源；来源类型和完整性必须符合
   `build-profile.md`，目标语料与可选对照语料必须由用户明确指定。
2. 在聊天中展示新 `profile_id`、规范化后的目标档案路径和事实审阅摘要。
3. 确认目标档案尚不存在。
4. 请求用户确认事实审阅结果和所展示的新档案目标。
5. 只有用户确认后，才在安全临时位置形成完整档案并校验。
6. 校验通过后一次性放入目标位置，再安全更新 `config.json`。

用户拒绝确认或任一步失败时，不创建目标目录、空配置、临时档案或部分文件。

## `update`

1. 校验默认档案、schema、必需文件和全部规范化路径。
2. 确认本次新增来源都是用户明确选择或直接粘贴的完整作品，且符合
   `build-profile.md` 的来源类型和完整性规则；否则停止。
3. 在聊天中展示将更新的档案路径、新增来源范围和预期变更。
4. 请求用户确认展示的变更范围。
5. 用户确认后，先按 `profile-schema.md` 完成完整备份。
6. 在安全临时位置生成并校验完整的新版本。
7. 只有备份和新版本都有效时，才一次性替换原档案。

更新失败时保留原档案和已经成功完成的完整备份，不留下半成品。不得把
`update` 当成修复未知 schema 的手段。

## `remember`

`remember` 只保存用户在当前请求中明确要求长期记住的偏好或纠正。

1. 先判断用户是否明确要求长期保存。只有“以后记住”“加入偏好”等清楚表达
   才授权持久化；“这次不要使用”等临时要求不授权写入。
2. 在聊天中复述准备保存的准确内容，并展示将修改的档案及
   `preferences.md` 路径。
3. 区分“用户明确偏好”和“用户明确反感”，不得把模型推测写入。
4. 长期保存意图明确时，不再追加 Meecho 对话确认；先备份，再安全改写和校验
   整个档案，完成后报告结果。
5. 意图含糊或没有可用默认档案时停止并询问，不得自行写入。

普通写作中的临时要求、模型从文章推测的规律、用户没有要求持久保存的反馈，
都不得自动进入 `preferences.md`。

## `switch`

`switch` 只改变以后未点名请求所使用的默认 voice。

1. 读取并校验 `config.json`，再按 `profile-schema.md` 只读枚举合法 voice。
2. 要求用户给出一个精确存在的 `profile_id`；不得模糊匹配。
3. 如果目标已经是默认 voice，直接报告“已经是默认 voice”，不申请写入，也不
   改写文件。
4. 否则展示当前默认 `profile_id`、目标 `profile_id` 和准确的
   `<USER_HOME>/.meecho/config.json` 路径。用户明确提出的切换请求已经授权
   这次配置变更，不再追加 Meecho 对话确认。
5. 在安全临时位置生成只含 `schema` 和 `active_profile_id` 的完整配置，校验后
   原子替换 `config.json`，再报告切换结果。
6. 不修改任何 profile 内容、`manifest.json`、备份或 `updated_at`。失败时保留
   原配置并清理本次临时内容。

## `export`

1. 展示规范化后的源档案路径和用户明确指定的目标路径。
2. 提醒用户导出副本仍包含私人声音信息，不应意外提交到 Git。
3. 确认目标不在插件目录、插件缓存或当前项目内。
4. 目标安全、准确且不会覆盖现有内容时，用户明确提出的导出请求已经授权创建
   该副本，不再追加 Meecho 对话确认。
5. 复制完整档案并校验副本，再报告实际目标路径。
6. 比较源档案前后文件清单与内容摘要，确保源档案没有改变。

`export` 不改变默认档案、不更新 `updated_at`，也不自动切换默认
`profile_id`。如果目标已存在，必须停止并让用户明确选择新位置或另行确认
覆盖；不得默认覆盖。

## `delete`

1. 解析并展示唯一、规范化的档案绝对路径。
2. 说明是否删除该档案的备份；默认保留备份。
3. 说明默认档案和 `config.json` 将如何变化。
4. 要求用户对所展示的准确路径进行第二次明确确认。
5. 只有第二次确认后，才能申请并执行该范围内的文件系统变更。
6. 只删除已经展示并确认的档案，不使用通配符，不扩大到其他档案。

第一次提出“删除”只是选择操作，不等于第二次确认。模糊答复、仅批准工具
权限或确认其他路径，都不能替代第二次明确确认。

## 权限被拒绝或操作失败

- 用户拒绝审阅确认、删除确认、覆盖确认或宿主工具授权后立即停止，不反复
  请求，不改用其他目录绕过拒绝。
- 需要确认但尚未取得确认时，不得先创建目录、锁文件、空文件、临时文件或备份。
- 已经写入安全临时位置但最终校验失败时，清理本次临时内容，并保留原档案。
- 不得留下可以被误认为成功档案的部分结果。
- 只在聊天中报告未执行的动作、准确目标和失败原因。
- 不把拒绝解释成允许只写一部分，也不自动降级为另一个管理操作。

## 写入前基线复查

多个客户端可以读取同一个 `.meecho`，因此 `update`、`remember`、`switch` 和
`delete` 使用乐观并发保护，不得静默覆盖另一个客户端刚完成的变更。

1. 准备操作时记录与本次变更相关的基线。`update` 和 `remember` 记录完整
   `config.json` 内容及目标 `manifest.json` 的 `updated_at`；`switch` 记录完整
   `config.json` 内容；`delete` 同时记录完整 `config.json` 内容及目标
   `manifest.json` 的 `updated_at`。
2. 完成审阅或确认后，在真正写入、替换或删除前重新读取同一组基线。
3. 只要文件消失、内容不同或 `updated_at` 发生变化，立即停止，不写入、不删除、
   不覆盖另一个客户端的结果，并提示用户重新发起操作。
4. 基线未变时才继续原有的备份、临时写入、校验和原子替换流程。

这项复查不创建锁文件，也不把客户端名称写入档案。只读操作不需要基线复查。

## 路径与隐私检查

每次准备变更前都执行以下检查：

1. 将所有路径转换为规范化绝对路径。
2. 档案和备份必须位于固定的 `<USER_HOME>/.meecho/` 内；Windows 映射为
   `%USERPROFILE%\.meecho\`，POSIX 映射为 `$HOME/.meecho/`。
3. `.meecho` 根目录和档案目录都不得是符号链接、目录联接或其他重解析点。
4. 导出目标必须是用户明确指定的位置，且不得位于 Skill 安装目录、客户端缓存
   或当前项目内。
5. 展示给用户的路径必须与实际操作路径完全一致。
6. 不记录原始作品文件路径、粘贴来源标签或原文到最终档案、Skill、项目或
   测试日志。
